# Web test fixtures: one generated factory per generated type

Status: design, for review by the FE lane controller (claude/5edf7bb5). Umbrella #564. Branch for the work: `feat/fe-fixtures`.
Measured on `origin/main` `02be34b7` (2026-10-19).

## 1. The problem (root cause)

`web/src/shared/api/generated/*.ts` is ts-rs output. Web tests build objects of these types **inline**, as literals annotated with the type, so tsc checks each one against the type.

When the back end adds a required field, every one of those literals stops compiling, including in test files far outside the BE ticket. PRs 3503 and 3533 went red this way on 2026-10-19.

Measured at `02be34b7`:

| What | Count | How |
|---|---|---|
| generated files | 155 | `ls web/src/shared/api/generated \| wc -l` |
| exported types | 498 (476 object types `= {`, 22 others) | `grep -h "^export type" …/generated/*.ts` |
| test files importing generated types | 278 | `git grep -l "shared/api/generated" -- '*.test.ts' '*.test.tsx'` |
| typed literals `const X: T = {…}` / `[…]` in tests | ≈400 (includes some local types) | `git grep -nE "^(export )?const \w+: [A-Z]\w*(\[\])? = [\[{]" -- '*.test.ts*'` |

The fix: **a test never writes a generated type's object by hand.** It calls a factory. A new field then breaks nothing outside one generated fixture file, and that file is regenerated by a command, not edited.

## 2. The shape

One factory per generated **object** type:

```ts
// web/src/shared/testing/fixtures/admin_cash.ts  (GENERATED — do not edit)
import type { AdminCashCountedItem, AdminCashData } from '../../api/generated/admin_cash';
import { makeOpenShiftDto } from './common';

export function makeAdminCashCountedItem(o: Partial<AdminCashCountedItem> = {}): AdminCashCountedItem {
  return { code: 'USD', amount: '0.00', ...o };
}
```

- **Signature:** `make<TypeName>(o: Partial<T> = {}): T`. The default object is spread first and the overrides last, so an override always wins. The return type is `T`, so tsc proves the defaults are complete.
- **Naming:** `make` + the exact exported type name. The fixture file has the same base name as its generated file: `generated/<name>.ts` → `testing/fixtures/<name>.ts`.
- **Generics:** `ViewAnswer<T>`, `OrgViewAnswer<T>` and `Part<T>` get generic factories that take the payload: `makePart<T>(data: T | null, o?: Partial<Part<T>>)`, `makeViewAnswer<T>(data: T, o?)`.
- **Not factories:** the 22 non-object types (string-literal unions such as `AdminTransactionStatus`, aliases such as `Money = string`, `MeView = Me`, and the `Record<symbol, never>` / `null` filters). Tests write those values directly; a new union member breaks nothing.

## 3. The factories are generated, not hand-written

Hand-written factories would drift the way the literals do: someone must remember to edit them. So:

- **`web/scripts/gen-fixtures.mjs`** reads every `generated/*.ts` as text. ts-rs writes each type from `export type X = {` to its closing `};`; fields are `name: T,` or `name?: T,`, and JSDoc comments can sit between fields (e.g. `admin_users.ts`'s `AdminUserRole`), so the parser strips comments first. It writes every `testing/fixtures/*.ts`, plus `testing/fixtures/index.ts` re-exporting them all. Run it with `npm run gen:fixtures`.
- **Defaults**, from the field's TS type and name, so they are stable and realistic:

  | Field type | Default |
  |---|---|
  | `T \| null` | `null` |
  | optional `f?: T` | omitted |
  | `string`, name is `id` or ends in `Id` / `_id` (not `paid`, `valid`) | `'<snake_type>-1'` (e.g. `'admin_cash_counted_item-1'`) |
  | `string`, name matches `amount\|price\|rate\|fee\|total\|balance\|quantity\|limit\|thb\|share` (any case) | `'0.00'`. Money and rates stay decimal **strings**, as the generated types are |
  | `string`, name ends in `At` / `at` / `date` / `Date` / `Time` | `'2026-01-01T00:00:00Z'` (a date-only name ending `Date`: `'2026-01-01'`) |
  | `string`, name is `currency` / `code` | `'USD'` |
  | other `string` | `'<fieldName>'` (e.g. `name: 'name'`) |
  | `number` | `0` |
  | `boolean` | `false` |
  | string-literal union | its first member |
  | `Array<…>` / `T[]` | `[]` |
  | `Record<…>` | `{}` |
  | another generated object type | `make<That>()`, imported from that type's fixture file (nesting composes) |
  | an alias to a union or `string` (`Money`, `Rate`, `AdminTransactionStatus`) | as its target |
  | `Part<T>` | `makePart(null)` |
  | `any` (6 files) | `null` |
- **Never edited by hand.** The header says so, and §4's check enforces it.
- **A new BE field** ⇒ the BE PR already regenerates `generated/*.ts` (`XC_UPDATE_GENERATED=1 cargo test --test v3_types_test`). It also runs `cd web && npm run gen:fixtures` and commits the fixture change. No test file changes unless a test asserts on that new field.

## 4. The guards (machine-checked)

1. **tsc:** each factory returns `T`, so an incomplete default fails `npx tsc --noEmit` in exactly one file.
2. **Fixtures are complete and current:** `web/src/shared/testing/fixtures/fixtures.guard.test.ts` runs `gen-fixtures.mjs` in check mode (in memory, no write) and fails, naming the files, when:
   - a generated object type has no `make<Name>` (a new type nobody generated for);
   - a committed fixture file differs from what the generator writes (a stale or hand-edited fixture);
   - a fixture file exists with no generated file.
   This runs in the web CI job with the rest of vitest, so a BE PR that changes a generated file and forgets `gen:fixtures` goes red in its own CI, not in someone else's.
3. **No inline generated objects in tests (the done rule):** `web/src/shared/testing/fixtures/no-inline-dto.guard.test.ts` reads every `*.test.ts(x)` under `web/src` as text and fails, naming file and line, when a test file:
   - imports from `shared/api/generated/`. Tests import types and factories from `shared/testing/fixtures`, which re-exports the types; or
   - writes a generated **object** type's name as an annotation, cast or constraint: `: Name`, `: Name[]`, `as Name`, `satisfies Name`, or a generic argument `<Name>` / `<Name[]>`. Type names are read from the generated files.
   - `fixtures/**` and the guard tests themselves are exempt.
   - **Rollout:** during the migration it reads an **allowlist** of the not-yet-migrated test files, one path per line, in `fixtures/inline-dto-allowlist/<folder>.txt` (one file per screen folder, §6). Each migration ticket deletes its folder's file. The allowlist may only shrink; the guard fails if it lists a file that is already clean. Done = the allowlist folder is gone.
   - **Known residual:** an object literal passed straight into a typed parameter or JSX prop, with no annotation (`render(<Row row={{ … }} />)`), is not caught by text. The repo's TypeScript 7 has no classic compiler API (`require('typescript').createProgram` is `undefined` at 7.0.2), so a type-aware check is not available. Such a literal still breaks when a field is added, and is then fixed with a factory call; migration tickets convert the ones they see.

## 5. How tests use it

```ts
import { makeAdminCashData, makeAdminCashCountedItem } from '../../../shared/testing/fixtures';
const data = makeAdminCashData({ counted: [makeAdminCashCountedItem({ code: 'THB', amount: '1500.00' })] });
```
- **The migration rule:** a literal `const X: T = { …fields… }` becomes `const X = makeT({ …the same fields… })`. Every field the old literal set is passed as an override, so **no assertion changes and no test relies on a default it did not set before.** Trimming overrides that equal the default is not part of this work.
- **Arrays:** `const ROWS: T[] = [ {…}, {…} ]` becomes `[makeT({…}), makeT({…})]`.
- **Nested literals:** nested generated objects become nested factory calls.
- **JSON bodies:** a fetch mock that returns JSON (`new Response(JSON.stringify(…))`) is not type-checked and need not change. The guard only flags typed uses.

## 6. Files and order

| What | Files | Who |
|---|---|---|
| Generator + guards + generated fixtures + allowlist (all 278 files listed) | `web/scripts/gen-fixtures.mjs`, `web/package.json` (`gen:fixtures`), `web/src/shared/testing/fixtures/**` | the sub-controller's **skeleton** on `feat/fe-fixtures` (tooling, plus a generated output nobody hand-writes) |
| Migration, one screen folder per ticket | that folder's `*.test.ts(x)` + deletes its own `inline-dto-allowlist/<folder>.txt` | Gemini, `class:mechanical` |

- **The one shared file is the allowlist.** Each ticket deletes only its own folder's lines, which is a line merge, never a conflict of meaning. To keep File scopes disjoint for the queue, the allowlist is **one file per screen folder**: `fixtures/inline-dto-allowlist/<folder-with-slashes-as-dashes>.txt`.
- **The migration tickets are cut by the folders that import generated types today** (top: `desk/bookings` 14, `admin/cash` 13, `desk/steps` 12, `admin/users` 10, …; about 60 folders). Small folders are grouped so each ticket is 4–12 test files, and two tickets never share a folder.
- **Done line:** on `feat/fe-fixtures`:
  - `fixtures/inline-dto-allowlist/` is gone, and guards §4.2 and §4.3 pass;
  - `npx tsc --noEmit` passes;
  - the full web suite (`npx vitest run`) is green on the Mac Studio (never Dell: it is the only Linux CI machine).
  Then `feat/fe-fixtures` → main.

## 7. What this design does not do

- No test assertion changes; only how fixture objects are built.
- No change to `generated/*.ts` or to ts-rs. The fixture generator reads its output as text.
- No backend change. The only BE-side habit added is running `npm run gen:fixtures` with `XC_UPDATE_GENERATED`; the BE ticket template should say so (a note to the BE controller on #564).

## 8. Decided by the lane controller (claude/5edf7bb5, review of PR 3559)

2. **Defaults: accepted as written** (currency `'USD'`).
